# Task 17 report — Bounded observability and optional OpenTelemetry

Implemented an additive event query contract and Read-authorized `GET /api/monitoring/executions/{id}/events` endpoint, with stable cursor paging capped at 100 rows. The SQL event writer validates source, code, fields, payload size, timestamp, and event identity; unique execution/attempt/source/sequence keys make retries idempotent. The query combines persisted supervisor events with mandatory attempt lifecycle rows and excludes arbitrary logs/details.

Added a bounded best-effort event queue, isolated log sink failures and invalid/flooded diagnostics, aggregation into SQL hourly totals, and built-in `WorkerDock` ActivitySource/Meter instruments. Handler diagnostics now cross the isolated executor IPC in separate allowlisted, redacted frames (4 KiB maximum, 256 per attempt, 32-frame executor queue) and are persisted through a bounded 64-event supervisor queue. Malformed or flooded frames, backpressure, and store failure drop diagnostics without changing terminal outcome or delaying supervisor termination. Cancel control remains duplex and terminal result follows queued diagnostic frames.

Attempt activity spans now emit trace identity and terminal outcome/exit/persistence status. Metric tags remain allowlisted and exclude execution/correlation identifiers. Aggregation uses a bounded batch in `ReadCommitted` with `UPDLOCK,READPAST,READCOMMITTEDLOCK` so concurrent workers claim distinct rows with RCSI-compatible locking. The worker catches optional aggregation failures. Authentication telemetry is not emitted because the host does not expose authoritative auth outcomes. Migration 0006 adds only AuditEvents SELECT to WorkerDockRuntime, preserving INSERT and adding no audit UPDATE/DELETE. The migration is manifest-hashed and rollback refuses to remove populated observability data.
