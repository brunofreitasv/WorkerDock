# Dynamic Template Values Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix SQL parameter authoring and provide predictable, typed dynamic values for scheduled and manual SQL, HTTP, and custom-template executions.

**Architecture:** Store a versioned binding plan alongside each immutable job revision. Capture an execution context at admission, assign its first-start timestamp once, and persist resolved nonsecret values before dispatching the template; retries reuse them. Shared validation and preview services serve the generic wizard, while SQL and HTTP adapters retain their parameter binding and serialization responsibilities.

## Locked interfaces and plan-level decisions

The spec fixes behavior; this section fixes concrete names and bounds. Types live in namespaces matching their directories. Enums serialize as their exact names, never integers. JSON uses web/camelCase naming and rejects unknown members.

```csharp
// WorkerDock.Contracts.Values
public enum DynamicValueSource { ReferenceDate, ScheduledTimestamp, FirstExecutionStart, ExecutionId, IdempotencyKey }
public enum DynamicValueBoundary { None, StartOfDay, EndOfDay, StartOfMonth, EndOfMonth, StartOfYear, EndOfYear }
public enum DynamicValueFormat { String, IsoDate, IsoOffsetTimestamp, IsoUtcTimestamp, UnixSeconds, UnixMilliseconds }
public sealed record DynamicValueBinding(string Target, DynamicValueSource Source,
    string? TimeZoneId, int Months, int Days, DynamicValueBoundary Boundary, DynamicValueFormat Format);
public sealed record DynamicValuePlan(int ResolverVersion, string TimeZoneId,
    IReadOnlyList<DynamicValueBinding> Bindings);
public sealed record ExecutionValueContext(int ResolverVersion, string TimeZoneId, string TriggerKind,
    DateTimeOffset? ScheduledForUtc, DateTimeOffset? RequestedAtUtc,
    DateOnly? ReferenceDateOverride, DateTimeOffset? FirstStartedAtUtc);
public sealed record DynamicValueSnapshot(int ResolverVersion, string InputDigest,
    IReadOnlyDictionary<string, JsonElement> Values);
public sealed class ValueResolutionException(string code, string target) : Exception(code)
{ public string Code { get; } = code; public string Target { get; } = target; }
```

`DynamicValueJson.Read(JsonElement value) -> DynamicValuePlan`, `Write(DynamicValuePlan plan) -> JsonElement`, and `Freeze(DynamicValuePlan plan) -> DynamicValuePlan` provide strict decoding/cloning. Resolver version is `1`. Maximum bindings `128`; pointer length `256`; zone ID length `100`; month offset `-1200..1200`; day offset `-36600..36600`; snapshot UTF-8 size `16384`. Out-of-calendar-range arithmetic fails with `DynamicDateOutOfRange` even within those bounds. Empty binding arrays are permitted for an explicitly pinned reference timezone.

Append optional `JsonElement? DynamicValues = null` to Domain `JobRevision`; Domain remains independent of Contracts. API/UI `dynamicValues` is serialized `DynamicValuePlan`. Append optional `ExecutionValueContext? ValueContext = null`, `DynamicValueSnapshot? ValueSnapshot = null`, and `string? ValueResolutionError = null` to Contracts `ExecutionDescriptor`. Existing fixed jobs use null for all three. Descriptor `Configuration` is fully materialized after preparation; the database job revision stays unchanged.

Add boolean scalar-schema annotation `x-workerDock-dynamicValue`. It is opt-in, cannot coexist with true secret/sensitive annotations or sit below such an ancestor, and cannot mark objects/arrays. Annotating an `items` property or `additionalProperties` scalar permits concrete descendants. Eligible SQL targets are `/parameters/<index>/value`; HTTP targets are `/parameters/<escaped-name>`; custom targets follow their schema. Profile, connection, SQL command text, and procedure names are not eligible.

Targets use RFC 6901 escaping (`~0`, `~1`), canonical nonnegative decimal array indices, and existing parent containers. Missing declared scalar leaves may be supplied by bindings. Reject root pointers, `-` append indices, malformed escapes, duplicate/ancestor targets, and undeclared properties. Never serialize unknown user keys in errors; use a safe binding-index path when a target is not schema-declared. Frontend rejects `__proto__`, `prototype`, and `constructor` in mutable dictionary helpers.

Identifiers allow `String` only and no date transforms; execution ID uses lowercase `N` format and idempotency key preserves its supplied value. ReferenceDate allows `IsoDate` only, no binding timezone override, and remains DateOnly. Timestamp sources allow ISO date/timestamp or Unix formats. ISO dates use `yyyy-MM-dd`, timestamp formats use round-trip `O` with offset or UTC `Z`, Unix formats produce JSON integers. Date period ends are inclusive; timestamp `EndOf*` is the next period's start, labeled “End (exclusive).” Only transformed local timestamps require DST gap/ambiguity rejection; untransformed instants preserve their offset during repeated hours. Accept IANA IDs or `UTC`, matching the scheduler; do not reference Quartz from Infrastructure.

Safe semantic codes: `DynamicBindingInvalid`, `DynamicTargetInvalid`, `DynamicSourceUnavailable`, `DynamicTypeMismatch`, `DynamicTimeZoneInvalid`, `DynamicLocalTimeInvalid`, `DynamicDateOutOfRange`, `DynamicSnapshotTooLarge`, `DynamicResolverUnsupported`, `DynamicSnapshotInvalid`. No raw values/exceptions are returned.
